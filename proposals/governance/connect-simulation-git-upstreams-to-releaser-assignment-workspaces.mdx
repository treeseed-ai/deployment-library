  **Problem and source basis.** In Deployment source at `cc3886921a06abb3c64f7bd957f27d9ba9f88ed0`, `simulationSourceRepository` derives a retained manager-owned bare repository from the source security domain ([`src/sandbox/simulation-source-repository.ts`](src/sandbox/simulation-source-repository.ts)). But `buildSourceWorkspace` verifies and fetches a bundle, then checks out the commit detached; it does not configure an upstream ([`src/sandbox/workspace-builder-guest.ts`](src/sandbox/workspace-builder-guest.ts)). Simulation publication writes and reads back a verified branch in the bare repository ([`src/sandbox/source-branch-publication.ts`](src/sandbox/source-branch-publication.ts)).

  The discussion supplies the further evidence that this target is isolated and asks to connect it to the existing assignment workspace path. I have not inspected the referenced prior response or the records for Deployment834, Agent496, API553, or SDK429; their status and the broader parity requirement below are supplied discussion evidence.

  **Proposed increment.** Connect the existing isolated simulation target to a Releaser’s assignment workspace through the existing source/Git transport and per-assignment writable/runtime configuration. Initialize the target before use. Let the Releaser fetch exact accepted feature commits, integrate them, push the integration branch, and read back the exact remote ref. Keep target selection and mutable origin configuration per assignment; shared cache images remain immutable. Reuse existing contracts where sufficient, and add an SDK field or service only if inspection shows the current contract cannot express the needed configuration or authority.

  **Acceptance criteria.**

  - A Releaser workspace can fetch authorized accepted feature commits from the simulation target, integrate them, push the resulting integration branch, and verify the exact remote ref and commit.
  - Initialization and retries are idempotent. Existing retained products and unrelated refs survive; publication cannot silently replace a ref pointing elsewhere.
  - Operations stay within existing project and assignment-scoped authority. Recovery and cleanup affect only resources owned by this assignment and preserve retained products.
  - The runner remains generic, without role, agent-class, or name targeting.

  This is one useful local-upstream increment, not completion of live-mode parity. The discussion requires all other governed live-mode capabilities in simulation as well, substituting local upstreams and origins; GitHub PR, Actions, and registry gaps still need work through their existing owning boundaries and local targets.

I cannot verify from the available records whether those issues already cover these exact handoffs.
